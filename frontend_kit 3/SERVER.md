# Живой бэкенд вместо фикстур

Фикстуры в `day-01/`, `day-02/`, `day-07/` никуда не деваются — на них
удобно верстать. Но интерфейс, где кнопка «авария» ничего не делает,
на защите смотрится плохо. Поэтому в стенде есть сервер, отдающий ровно
те же четыре формы, только вживую, и умеющий пересчитывать день.

Переход с фикстур на сервер — это замена одной строки:

```js
fetch('day-01/plan.json')            // было
fetch('/api/plan?day=1')             // стало
```

Формат ответа тот же самый, `CONTRACT.md` продолжает действовать.

## Запуск

Нужен Python 3.10+ и папка `vrptw/` из стенда. Ничего ставить не нужно
сверх `numpy` и `scipy` — сервер написан на стандартной библиотеке.

```bash
cd <папка, где лежит vrptw/>
pip install numpy scipy
python3 -m vrptw.server
```

Первый запуск считает день (около минуты) и кладёт результат в
`.vrptw-cache/`, дальше поднимается за пару секунд. Сервер слушает
`http://localhost:8000`, описание всех путей — на `http://localhost:8000/api`.

Проверить, что всё живо, не открывая браузер:

```bash
python3 -m vrptw.server check
```

## Пути

| Запрос | Что вернёт |
|---|---|
| `GET /api/plan?day=1` | маршруты, карта, таймлайн — то же, что `plan.json` |
| `GET /api/explain?day=1` | панель «почему так» |
| `GET /api/simulation?day=1` | сводка дня и хрупкие визиты |
| `GET /api/shifts?day=1` | график выхода: спрос против смен |
| `GET /api/day?day=1` | все четыре формы одним ответом |
| `GET /api/days` | какие дни готовы, какие можно попросить |
| `GET /api/tuned?day=1` | план того же дня по **подобранному** графику смен |
| `GET /api/replan?day=1&at=820&urgent=2` | пересчёт: аварии в 13:40 |
| `POST /api/replan` | то же телом `{day, at, urgent, seconds, run}` |

`day` — номер дня от 1 до 30. Разные номера дают разные дни: удобно,
чтобы вёрстка не оказалась подогнанной под один набор.

## Пересчёт — то, ради чего сервер и нужен

```js
const r = await fetch('/api/replan?day=1&at=820&urgent=2').then(r => r.json())
```

`at` — момент в минутах от полуночи (820 = 13:40), `urgent` — сколько
аварий приходит в этот момент. В ответе обычный `plan`, но на **остаток
дня**, плюс блок `meta.replan`:

```jsonc
"replan": {
  "at": 820,
  "solve_seconds": 1.5,        // сколько думал планировщик
  "stability": 1.0,            // доля визитов, сохранивших исполнителя
  "urgent_ids": ["U00", "U01"],
  "urgent_assigned": 2,        // сколько аварий влезло в план
  "done_before": ["R0004"],    // что уже выполнено к этому моменту
  "failed_before": {"R0011": "no_show"},   // и что уже сорвалось
  "assigned_now": 24,          // столько визитов в новом плане
  "assigned_as_is": 22         // столько было бы, если не пересчитывать
}
```

Разница `assigned_now` против `assigned_as_is` — это и есть цена
пересчёта в визитах, её стоит показать на экране. `stability` —
вторая цифра для показа: план не перетасовывает людей, которым уже
сказали ехать.

Один и тот же `run` даёт один и тот же ход дня, поэтому демо
воспроизводится: нажали второй раз — получили то же самое. Меняете
`run` — получаете другой случайный день.

## Интерфейс с того же адреса

Если положить собранный фронт в папку `web/` рядом с `vrptw/`, сервер
начнёт раздавать её сам:

```
проект/
├── vrptw/
└── web/
    └── index.html
```

Тогда всё открывается с `http://localhost:8000`, и вопрос CORS не
возникает вовсе. Это самый надёжный вариант для защиты, где браузер
чужой и настроек в нём не поменять.

Если фронт удобнее держать на своём dev-сервере (Vite и подобное) —
тоже работает: сервер отдаёт `Access-Control-Allow-Origin: *`, запросы
с другого порта проходят.

## Что учесть

**Первый запрос по новому дню считается несколько секунд.** Дни 1, 2, 7
можно прогреть заранее: `python3 -m vrptw.server 8000 1,2,7`. Остальные
считаются по требованию и потом лежат в кэше.

**`/api/tuned` — самый медленный, около минуты на новый день.** Он
подбирает график смен настоящим солвером. После первого раза — мгновенно.

**Пересчёт занимает полторы секунды** — это не задержка сети, это
работа планировщика. Полторы секунды на экране лучше показать честно
(спиннер с надписью «пересобираю маршруты»), чем прятать: это ровно та
цифра, которой мы хвалимся.

**Кэш живёт в `.vrptw-cache/`.** Если поменяется солвер, кэш надо
удалить или запрашивать с `&fresh=1`, иначе будете смотреть на старые
числа.
